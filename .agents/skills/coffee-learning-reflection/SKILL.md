# Coffee Learning Reflection

Use this skill when the user asks to review, reflect on, organize, or learn from a coffee tasting note, bean record, brew log, or `coffee-asset` case study. The goal is learning and taste calibration, not article production.

## Core stance

- Treat the user's raw tasting words as primary evidence. Preserve their phrasing before improving wording.
- Do not turn the note into blog prose unless the user explicitly asks.
- Separate what is known, what was perceived, and what is inferred.
- Prefer questions and small experiments over confident conclusions.
- When proposing a next step, choose one main variable: grind size, water temperature, ratio, pouring, brew time, water, or tasting timing.

## Reflection format

When useful, respond with these sections:

### 1. Observation Split

- **Facts**: bean data, recipe, method, temperature, grind, time, roast, process, date, equipment.
- **Perception**: aroma, flavor, acidity, sweetness, body, aftertaste, temperature changes, personal reactions.
- **Hypothesis**: extraction, roast, process, origin, freshness, water, grinder, or tasting-condition explanations.

### 2. Learning Feedback

- Identify where the note is clear.
- Identify where the note mixes observation and interpretation.
- Convert vague phrases into questions the user can test next time.
- Name missing data only when it would materially improve learning.

### 3. Knowledge Connections

Connect the note to relevant local knowledge when possible:

- `00_principles/` for extraction, acidity, bitterness, sweetness, temperature, processing, and origins.
- `01_frameworks/` for tasting method, evaluation scale, tongue calibration, and improvement loops.
- `03_patterns/` for recurring insights across multiple case studies.

State connections as candidates when the evidence is incomplete.

### 4. Next Experiment

Suggest one small experiment for the next brew or tasting. Explain what it is testing and what result would support or weaken the hypothesis.

### 5. Asset Update

Suggest where the insight belongs in `coffee-asset`:

- keep it only in the case study
- link it to an existing principle or framework
- add a pattern candidate to `03_patterns`
- hold it as an unresolved question

Avoid recommending blog conversion until the insight is stable enough that the user can explain it in their own words.
