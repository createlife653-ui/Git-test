# 学習記事ワークフロー

`coffee-blog` の記事は、公開用コンテンツを量産するためではなく、コーヒーの理解を定着させるために書く。

合言葉は「教えるつもりで、自分が本当に分かっているか確認する」。

## 1. 記事にする前に確認する

まず `coffee-asset` 側で、以下を分ける。

- **Facts**: 豆、産地、精製、焙煎、抽出条件など。
- **Perception**: 自分が感じた味、香り、飲み心地。
- **Hypothesis**: なぜそう感じたのかの仮説。
- **Next experiment**: 次に1つだけ変える条件。

この4つが曖昧なままなら、まだブログ記事にしない。

## 2. 記事の型

記事には、できるだけ以下の流れを入れる。

```markdown
---
title: '記事タイトル'
slug: 'article-slug'
category: 'Learning Note'
date: 'YYYY-MM-DD'
readTime: '5 min'
image: '/images/...'
tags: ['Acidity', 'Brewing']
excerpt: 'この記事で確認した理解を1〜2文で書く'
---

## きっかけ

何を飲んだ、何に疑問を持った、何が分からなかったか。

## 今回説明したいこと

この記事で扱う理解を1つに絞る。

## 自分の観察

Facts と Perception を混ぜずに書く。

## いまの理解

原理や過去の記録とつなげて説明する。

## 今回理解したこと

自分の言葉で短くまとめる。

## まだ分からないこと

次に観察したいこと、試したいことを残す。
```

## 3. AIの使い方

AIは文章の代筆者ではなく、学習相手として使う。

- 事実、感覚、仮説が混ざっていないか確認する。
- 説明が飛躍していないか質問してもらう。
- 関連しそうな `coffee-asset` のファイルを探す。
- 最後に、読みにくい表現だけ軽く整える。

避けること。

- 本文を丸ごとAIに作らせる。
- 自分が観察していない味を足す。
- SEOや収益を目的に見出しを盛る。

## 4. ファイル作成ルール

- 記事は `content/posts/` に置く。
- ファイル名は英数字とハイフンのみ。
- `slug` はファイル名と合わせる。
- 画像は必要なら `public/images/` に置く。

## 5. 確認方法

```bash
cd coffee-blog
npm run dev
```

`http://localhost:3000/blog/[slug]` を開いて確認する。

## 6. 記事を書いた後

記事を書いて終わりにしない。

- 書いていて曖昧だった点を `coffee-asset/04_meta/` や該当ファイルに戻す。
- 新しいパターンが見えたら `coffee-asset/03_patterns/` に追加する。
- 次の抽出で試すことを1つ決める。
